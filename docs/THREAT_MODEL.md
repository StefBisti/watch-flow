# WatchFlow — Threat Model

Last reviewed: 2026-09-04

WatchFlow runs user-authored flows that fetch arbitrary URLs on a schedule and
notify the owner when something changes. The defining risk is that **the URL,
the selectors, the regexes and the webhook target are all attacker-controlled
input**, and we execute them on our own infrastructure.

Method: STRIDE per asset.

| Asset                             | Threat                                                              | STRIDE                     | Mitigation                                                                                                                                                                                                                      | Status                                                                                          |
| --------------------------------- | ------------------------------------------------------------------- | -------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------- |
| Internal network / cloud metadata | User points a fetch at `169.254.169.254`, Redis, or an RFC1918 host | Info disclosure, Elevation | `urlPolicy` blocks non-public IPs, non-http(s) schemes and ports outside 80/443; DNS resolved once and pinned into the undici agent so the address cannot change between check and connect; every redirect re-validated (max 3) | PARTIAL - Worker not yet on an egress-only host — week 3                                        |
| Other users' watches              | IDOR via guessed watch IDs                                          | Tampering, Info disclosure | cuid IDs; every query and mutation scoped `where: { userId }` rather than fetch-then-check                                                                                                                                      | PARTIAL - No IDOR regression tests yet — week 4                                                 |
| User-supplied API tokens          | Leak via logs, DB dump, or the client                               | Info disclosure            | AES-256-GCM at rest; `redact()` scrubs secrets from run logs; secrets never returned to the browser                                                                                                                             | PARTIAL - Decrypt key not yet worker-only, `{{secret.X}}` resolution unbuilt — week 3           |
| Worker host                       | Malicious HTML/JSON/regex payload exploits a parser                 | Elevation, DoS             | 2 MB response cap, 10 s fetch timeout, `jsonpath-plus` with `eval: false`, `safe-regex2` rejects catastrophic patterns, input caps on every config field                                                                        | PARTIAL - Non-root read-only container — week 3                                                 |
| Third-party sites                 | WatchFlow used to scrape or DDoS someone                            | Abuse                      | Per-node and per-run timeouts bound outbound work                                                                                                                                                                               | NOT IMPLEMENTED - Per-host rate limit week 3; min interval, max watches, robots.txt week 5      |
| Session                           | CSRF, session fixation, token theft                                 | Spoofing                   | Auth.js with database sessions (server-side revocable), GitHub OAuth, built-in CSRF on auth routes, Next.js origin checks on Server Actions                                                                                     | PARTIAL - maxAge is 7 days and cookie flags are defaults — tighten and set explicitly in week 4 |
| Webhook targets                   | Notifications used to reach the receiver's internal URLs            | Elevation                  | Same `safeFetch` and `urlPolicy` as any other fetch — no separate path                                                                                                                                                          | IMPLEMENTED                                                                                     |
| Email                             | Spam third parties                                                  | Abuse                      | v1 sends only to the watch owner's verified account address                                                                                                                                                                     | IMPLEMENTED                                                                                     |
| Supply chain                      | Malicious npm package or compromised GitHub Action                  | Tampering                  | `pnpm-lock.yaml` + `--frozen-lockfile`; every Action pinned to a commit SHA; Dependabot alerts, security updates and weekly version updates; `pnpm audit` gates at high; Trivy `vuln` scan                                      | PARTIAL - No `minimumReleaseAge`, no npm provenance check — week 5                              |
| Secrets in repo                   | Accidental commit of a key                                          | Info disclosure            | Gitleaks in pre-commit and CI; GitHub secret scanning with push protection; `.env*` gitignored; Doppler for local secrets                                                                                                       | IMPLEMENTED                                                                                     |
| Availability                      | Runaway flow or queue flood                                         | DoS                        | 25 nodes / 50 edges per flow, 10 s per node, 30 s per run, 10 KB cap per node output                                                                                                                                            | NOT IMPLEMENTED - Queue concurrency limit and depth alerting — week 3                           |
| Own source code                   | Bypassing the SSRF choke point                                      | Elevation                  | Semgrep rule bans `fetch`, `undici`, `axios`, `node:http`/`node:https` outside `packages/security`; pnpm's strict layout blocks undeclared deps; CodeQL `security-extended`                                                     | IMPLEMENTED                                                                                     |
| Actions of a compromised account  | Silent data changes with no trail                                   | Repudiation                | `AuditLog` model exists in the schema                                                                                                                                                                                           | NOT IMPLEMENTED - No writes yet — week 5                                                        |
